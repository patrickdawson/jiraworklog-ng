# Tauri migration: plan and state

Branch `tauri-rewrite` (not pushed). Last updated 2026-11-11, after milestone 6.

## Goal

Replace Electron + embedded Next.js server with Tauri 2: a Rust backend and a
React SPA in WebView2. The goals are a smaller download, less RAM and a faster
start. The Electron app on `main` keeps working and is the reference
implementation until the cut-over.

| | Electron 0.8.0 | Tauri (skeleton, milestone 1) |
|---|---|---|
| Installer | ~96 MB | 1.9 MB |
| Installed | 328 MB | ~9 MB exe |

The finished app is expected at 8–15 MB (PDF engine, views).

## Decisions

- **Everything except the views is Rust:** SQLite, migrations, all server
  actions, the domain logic, the Jira client, PDF, tray, menu and away
  detection.
- **UI:** Vite + React 19 + Tailwind 4 SPA. The components come over from
  `src/components/` nearly unchanged (see "How the UI port works").
- **E2E:** port the 15 Playwright specs to WebdriverIO + `tauri-driver`
  (milestone 9), plus Rust unit tests.
- **Desktop only:** browser mode ("Läuft im Browser" in the README) goes away.
- **Same data folder:** `%APPDATA%\jiraworklog-ng\jiraworklog.db`, named after
  package.json `name`. `%APPDATA%\JiraWorklog` is a stale copy from July; do
  not use it.
- **Jira credentials stay in the `settings` table** so the old and new app stay
  compatible. Moving them to the Windows Credential Manager (`keyring`) is
  optional, after the Electron app is retired.

### src-tauri

- `commands.rs`: settings, `buchen_data`, `kalender_data`, `auswertung_data`,
  `group_entries`, timer, entries, group colors, away,
  `show_window`, auto-launch, Jira (`preview_*`, `submit_*`,
  `test_jira_connection`), `get/set_force_booking`, `cleanup_old_entries`.
  Errors reach the UI as strings (`CommandError`). Submit and connection
  test are async + `spawn_blocking`; the DB mutex is held only to plan and to
  mark each sent worklog, never during HTTP.
- `events.rs`: `TimerStopped`, `AwayEnded`, `Navigate` (typed via tauri-specta).
- `tray.rs`, `menu.rs`, `window.rs`: tray, app menu, close-to-tray.
- `power.rs`: hidden top-level window (class `JiraWorklogPowerWatcher`) for WTS
  lock/unlock and `WM_POWERBROADCAST`. It is not message-only, because those
  windows get no broadcasts.
- `state.rs`: `Db` (mutex), `ForceBooking` (in memory only), `Zoom`, data paths.
- Plugins: single-instance, log (`tauri-main.log` next to the DB, local time),
  autostart (Run key `JiraWorklog`), dialog, opener.
- `build.rs` embeds a Common-Controls v6 manifest into every binary.
  Without it, the test harness aborts with `STATUS_ENTRYPOINT_NOT_FOUND`.

### ui

- `App.tsx`: hash router, layout (sidebar, confirm dialog, Jira URL, theme),
  `DesktopBridge`, `AwayDialog`. Buchen, Kalender and Auswertung are ported;
  Einstellungen and Hilfe show "Noch nicht portiert".
- `pages/*.tsx` load one command's view model each via TanStack Query.
- `lib/timeline.ts` (calendar lanes, gaps, overlaps) stays TypeScript: it is
  view geometry and re-runs every second while a timer runs.
- `components/auswertung-export.tsx` only has `RangeControls`; the two PDF
  buttons ("Als PDF", "Axapta-Bericht") come back with milestone 7, as does
  `lib/category-report.ts` (only the PDF uses it).

#### How the UI port works

Copy the component from `src/components/` and change as little as possible:

- `next/link` and `next/navigation` are aliased (vite.config.ts, tsconfig
  paths) to shims in `ui/src/next/` on top of react-router.
  `router.refresh()` = invalidate all queries.
- `ui/src/lib/actions.ts` keeps the old server-action names and signatures but
  calls Tauri commands, then invalidates all queries (= `revalidatePath`).
  It already has the settings-page actions `testJiraConnection`,
  `get/setForceBooking` and `cleanupOldEntries` for milestone 8.
- `ui/src/db/schema.ts` and `ui/src/lib/entries.ts` re-export generated types
  (use the `_Serialize` variants for data coming from Rust).
- `window.electron` → `desktop` from `ui/src/lib/desktop.ts` (same API).
- Strip `"use client"`. `process.env.NEXT_PUBLIC_APP_VERSION` is defined by Vite.
- A server-component page becomes a client page that loads one command's view
  model with `useQuery`.
- `f64` fields in Rust need `#[specta(type = crate::JsNumber)]`, otherwise TS
  gets `number | null`.

### Deviations from the Electron app (milestone 6)

- **TLS:** the old app set `NODE_TLS_REJECT_UNAUTHORIZED=0` unless
  `JIRA_TLS_STRICT=1`, so it never checked certificates. The new client
  checks them against the Windows store (corporate CAs included). The TLS
  error text no longer mentions `JIRA_TLS_STRICT`; it says the certificate
  must be trusted in Windows. Mention this in the CHANGELOG at cut-over.
- Connection errors: Node's "fetch failed" made every network error look like
  a TLS problem. Now only certificate/TLS errors get the TLS text; the rest
  get "Keine Verbindung zum Server. Bitte Jira-URL prüfen. (…)".
- Requests time out after 60 s (Node fetch had no limit).
- `cleanupOldEntries` with fractional days rounds up to whole days.

## Rules learned the hard way

- **Never target processes by name.** The installed Electron app runs as
  `JiraWorklog.exe`, and Windows process names match case-insensitively. A
  `Get-Process jiraworklog | Stop-Process` killed the live app once. Match the
  full path (`C:\dev\jiraworklog-ng\target\debug\jiraworklog.exe`), and find
  Vite by its command line.
- **Never write to the live DB.** Work on `data/real-copy/`; open the live DB
  read-only at most.
- **`tauri dev` restarts the app on every Rust change**, including
  `cargo fmt`. In-memory state such as a simulated lock is lost.
- `cargo search` needs `--registry crates-io`; crates come from the
  corporate kellnr mirror.
- A `location.hash = ...` set by a CDP script right after a router
  navigation can be lost; click the app's own links instead.
- New drizzle-style migrations need `when` > 1779340767574 and an entry in
  `crates/core/src/migrations.rs`.
